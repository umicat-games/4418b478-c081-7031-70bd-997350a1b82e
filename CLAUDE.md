## Empty-hand hover-inspect (white ring + name) (2026-08-07)
With NO tool/seed/material held, hovering the world shows a **white corner-bracket hugging the object under the mouse + its NAME on a small pill above it** (Stardew/Don't-Starve "inspect" affordance). It **ADDS to the normal triangle mouse cursor (`triangle_mouse_icon_1.png`) — never hides or replaces it**; over empty ground there's just the usual cursor (an earlier cut drew a small ring dot / hid the cursor on focus — both removed per the user). **`HoverScene`** (`src/scenes/HoverScene.ts`, registered in main.ts, launched + `bringToTop`'d with the HUD but BELOW `CursorScene` so the pixel cursor stays topmost) is a screen-space overlay that renders the ring + label from the **`hover` registry model** (`{visible,onObject,x,y,w,h,name,nameX,nameY}`) — screen-space so the zpix text stays crisp at any camera zoom. GameScene owns it: **`updateHoverInspect()`** runs each frame AFTER `updateTileCursor` (so it can override `cursorState.visible=false` to make the ring the cursor when locked); gated to empty hand (`activeTool==='hand' && !activeSeed && !activePlace`) + not blocked (dialog/menu/craft/confirm/build-palette/swing) + not over the hotbar (`overHotbarAt`). Source point = `vcursor` when locked, else `input.activePointer` (so it works BOTH pointer-locked AND unlocked; mouse-only, touch has no hover). **`hoverTargetAt(wx,wy)`** returns the topmost nameable object + the sprite the ring hugs. **The frame hugs the OPAQUE-PIXEL bbox, not `getBounds()`** — `spriteWorldSolidRect(sprite)` maps `frameSolidRect(texKey, frame.name)` (the cached opaque-pixel bbox, same helper the wall/door colliders use; widened to accept string atlas frame names) into world coords (full-frame `getBounds()` inset to the solid region, flip-aware), so the bracket hugs the ART regardless of each asset's transparent padding (a 48×48 Cato/tree frame whose art fills a small patch → tight box, not a floating frame). Was `getBounds()` first cut → the frame floated way off padded sprites (user-flagged), priority Cato → interactables (mailbox/chest/pad-shop/work-station, by their `*Contains` helpers) → trees/big-stones/foragables (tall, by `treeAtPoint`/`stoneAtPoint`/`foragAtPoint` sprite-bounds) → cell props (bushes/crops by tile lookup). The sprite's world `getBounds()` is projected to screen via `(wx - cam.worldView.x) * cam.zoom` (center-zoom). The object frame is the **`white-corner-bracket` 9-slice** (from the `ui-sheet` atlas = `all_ui_assets_on_one_sheet`; region-tagged as a nine-slice in the Asset Manager, 32×32 / 14px corners → four crisp corner marks, transparent stretchy edges) via `add.nineslice('ui-sheet','white-corner-bracket',w,h,14,14,14,14)` with a `w/h≥28` min guard; the empty-ground dot stays a drawn ring. **Its frame lives on the CDN atlas json** (`atlasLoadUrl`), mirrored into the LOCAL `public/uploaded/all_ui_assets_on_one_sheet.json` (which BootScene's `load.atlas('ui-sheet',…)` reads) — re-sync the local json from the CDN when new regions are tagged. Names = a new **`hover_*` i18n table** (`hover_tree_peach`→桃树/Peach tree, `hover_bush_grape`→葡萄藤, `hover_cato`, `hover_mailbox`/`_chest`/`_shop`/`_workstation`, forage/stone), crops reuse `item_crop_<name>`. **Caveat:** Cato's ring is a touch loose (his 48×48 sprite has transparent padding, so the bounds ring is bigger than the visible cat — tighten with a per-target inset if it bothers). Verified in prod (SwiftShader): ring+name over Cato / peach tree / grape bush + the locked empty-ground dot. Placed walls/furniture are NOT yet nameable (deferred — the player placed them).

## Scene-switch transitions (2026-08-05)
`TransitionScene` (`src/scenes/TransitionScene.ts`, registered LAST in main.ts, **launched once from `BootScene.create`** — guarded `isActive` so return-to-title's re-entry doesn't double-launch) is a global overlay that wipes between scenes with **circle iris / slide / dissolve**. Driven by **`src/transition.ts`**: the OUTGOING scene calls `startTransition(from, toKey, data, { effect, color, ms, focus, onCovered })` → the overlay COVERS (effect-specific tween), runs `onCovered` + `from.scene.start(toKey)`, then WAITS; the INCOMING scene calls `finishTransition(this)` when ready (an **8s safety** uncovers regardless) → it UNCOVERS (reverse tween). `startTransition` falls back to a plain `scene.start` if the overlay isn't running.
- **circle** = a full-screen curtain (Rectangle) masked by an **inverted** geometry-circle mask (`mask.invertAlpha=true` → curtain shows OUTSIDE the hole); the hole (a `make.graphics` stencil, NOT on the display list) scales `maxR→0` to cover, `0→maxR` to reveal, centred on `focus` (default screen centre). **slide** = curtain x `-W→0` then `0→+W`. **dissolve** = curtain alpha `0→1` then `1→0`. 420ms default, **DEF_COLOR `0xffffff` (white curtain)** — per-call `color` overrides.
- **Wired**: **Play** (BootMenu→Game) = `circle` iris; `GameScene.markReady` calls `finishTransition` (so the game shows only once the world + save are ready — the iris holds over GameScene's own loading cover). **Return-to-title = `dissolve` + a HARD `window.location.reload()`** (`coverAndReload` → `TransitionScene.coverAndHold`, cover then run a cb, NO scene switch/reveal): `returnToTitle` flushes the save (awaited), `clearData` deletes it, then reloads. **Why a reload, not `scene.start('BootScene')`:** Phaser REUSES the scene instance across restarts, so a Game→title→Game round-trip left `gameReady=true` (+ stale world collections) → `markReady` bailed → the loading cover + iris never cleared while the re-launched HUD showed (the "re-enter game stuck on loading" bug). A reload guarantees a clean slate. Verified via SwiftShader (iris mid-close + full reveal into the playable game).
- To transition another switch: `startTransition(this, 'Key', data, { effect })` + have the target call `finishTransition(this)` when ready. Effect is per-call — swap `'circle'`/`'slide'`/`'dissolve'` freely.
- **BGM crossfades with the wipe**: `TransitionScene.begin` calls `fadeBgmTo(this, 0, coverMs)` (src/bgm.ts) to **duck the outgoing track to silence as the screen covers** (the fade runs on the persistent TransitionScene so it survives the switch); the incoming scene's `crossToBgm(scene, key, stopKeys, fadeInMs)` **swells the new track in from 0** (700ms; also a soft intro on a cold boot). So title↔game music fades down then up in step with the visual transition instead of hard-cutting.

## Headless SCREENSHOTS now work (2026-07-29) — big deal for visual tuning
Older notes say "headless WebGL renders black, so nothing visual is verifiable" — that's **no longer true**. Launch Chromium with **`--use-gl=angle --use-angle=swiftshader --ignore-gpu-blocklist`** and the game canvas renders in software GL, so `page.screenshot()` captures the ACTUAL UI (not black). Drive it via the `?umicatScene=main` preview + `window.__game` (temp handle), then `sharp().extract()` a region + upscale to eyeball layout. This found the scroll-bar bug directly. Two caveats: (1) software-GL **alpha blending can differ** — a full-panel "transparency" in one shot was a render artifact, not a real bug (re-shot opaque), so sanity-check translucency across a couple of frames; (2) it's slower. Prefer this over the old sharp-mock workflow for anything already wired up. **CDP touch** (`ctx.newCDPSession` → `Input.dispatchTouchEvent`) drives real touch swipes (synthetic `PointerEvent{pointerType:'touch'}` does NOT set Phaser's `wasTouch`).

## What game is this?
**Title**: Catopia
**Genre**: Nurturing / Social / Simulation / Farming
**Core mechanic**: The player guards **Cato**, an AI-driven island spirit (a cat). Cato has autonomous behavior (algorithmic wander) AND runtime-AI conversation + **actions** (he can be asked, in chat, to farm). The player also farms directly (hoe / seeds / watering can via a hotbar). Bond = **guardian ↔ guarded spirit** (Pokémon-like, NOT parent/child).

## House building (2026-07-20)
Minecraft-style building: the player places wooden **walls**, an animated **door**, and **furniture** from the backpack to build Cato a house (no crafting yet → backpack is pre-stocked with materials, generous counts). **There's no player avatar** — Cato is the only physics body, so walls constrain *Cato* and the door opens for *Cato*. Assets (Sprout Lands premium "Building parts") imported via the Asset Manager → synced to `public/uploaded/`, loaded in BootScene (`house-walls`/`furniture`/`door` all **16×16**); door-open/close anims registered in BootScene. **Door slicing gotcha (2026-07-21):** the door sheet (288×32) is 18 cols × **2 rows of 16×16** — the door + its swing is the **TOP row** (frames 0=open … 5=closed); the bottom row is separate wall blocks. Slicing it as 16×32 stacked a block UNDER the door (the "门下面带个方块" bug) — it's 16×16, top row only.
- **Placeable items** — `ItemStack` gained `place?: 'wall'|'door'|'furniture'` + `variant?` (furniture piece). `makePlaceable` factory + `itemFromId` round-trip (ids `wall`/`door-item`/`furn-<piece>`). `setupInventory` seeds a wall on the hotbar (slot 7, was the unused axe) + door/furniture in the backpack. Icons render from the new sheets (`iconFrame` widened to `string|number`).
- **Placement mode** — selecting a material sets `activePlace` (in `equipSelected`, parallels `activeSeed`). `updateTileCursor` shows a semi-transparent **ghost** at the hovered cell (red when invalid) instead of the tool bracket; `canPlaceAt` = on-island, empty (no crop/placed), not under Cato. `actAt` places (priority) / **empty-hand click removes** a placed piece (refunds the material). `placeObject`/`removeObject`/`restorePlaced` mirror the crop pattern (origin bottom, `depth=footY` at cell BOTTOM so Cato y-sorts front/behind).
- **Wall orientation via a CONTEXTUAL 3×3 build palette (2026-07-21)** — R-to-rotate was invisible + touch-hostile. Picking the facing is now a **contextual menu at the build spot**: holding the wall item, you **tap a valid grass cell → a 3×3 palette pops up AROUND that cell** (`PaletteScene`, a registry-driven native-px overlay like `HotbarScene`; the 8 cells mirror the nine-slice — tap the top cell = top wall, a corner = that corner; centre = the target cell), **tap an orientation → the wall is placed there**; tap away = cancel. (Chosen over an always-on palette-on-tool-select: building is rare, so picking each time is fine and more discoverable/less clutter — see image #17 radial-menu inspiration, done as a rect grid.) `buildPaletteCell` = the pending cell (non-null = palette open); `openWallPalette` computes the cell's SCREEN pos (**`worldView`, not `scrollX` — center-zoom**) → `publishBuildPalette(sx,sy)` → `buildPalette` registry key; the scene writes cell hit-boxes to `buildPaletteBounds`; while open, `actAt`→`handlePaletteClick` consumes the tap (pick→`placeObject` at the pending cell, or miss→cancel). Opening/tool-change/inventory/dialog all `closeWallPalette`. The hover ghost (before the tap) previews the last-used facing; **R** cycles that default. `WALL_PALETTE` is the 3×3 layout (null centre), `WALL_ORIENTS` its non-null filter; `WALL_FRAME.window` (frame 6) kept only for the old-save FLOOR migration.
- **Only WALLS need orientation — everything else is its own item (2026-07-21):** `PlaceKind` = `wall|floor|window|door|furniture`. `setupInventory` seeds a **wall** on the hotbar + **floor** (`FLOOR_FRAME=6`, brick, non-solid) / **door** / **8 separate furniture items** (one per `FURNITURE` piece, `makePlaceable('furniture', …, pieceId)`) in the backpack — no palette, no R cycling. `equipSelected` sets `activePlace`/`activeFurn` from the selected item; `placeAppearance` branches per kind. **Window** (`WINDOW_FRAME=13`, a solid wall-with-window — frame 13 = row2/col3, a wooden segment with a glass pane) is its own backpack item, seeded next to the floor (2026-07-21); it needs no orientation (single design) and places directly like floor/door (`activePlace==='window'` → `placeObject`, no palette). It's solid (collides like a wall) and participates in OVERWRITE (swap a wall↔window in a run). `ensureBuildingMaterials` grants floor + **window** + all 8 furniture to old saves.
- **OVERWRITE placement (2026-07-21)** — `canPlaceAt` allows an already-occupied `placed` cell: placing OVER a piece **replaces** it (`placeObject` does `removeObject` first → the old piece is refunded, so a swap costs nothing net and fixing a mis-placement is free — no need to hoe it out first). Still blocked on farm tiles (crop / tilled soil) + under Cato. (Walls/door/window/furniture overwrite each other in `placed`.) The hoe removal is kept for actually taking a piece back.

- **Collision — authored in the Tileset Editor UI (2026-07-21):** one `wallGroup = physics.add.staticGroup()` + a single `collider(child, wallGroup)`; each solid cell = invisible static body(ies) (`addSolid`, `__WHITE` + `setDisplaySize`+`refreshBody`). A side-wall's art is only a thin strip in its 16×16 cell, so a full-tile collider blocked Cato in empty space. **Real-user fix:** the wall PNG is configured as a **tileset** (`PATCH /assets/{id}/tileset`, asset `3915b0b9…`; 16×16, 5×3) and each wall tile's collision is **authored in the Tileset Editor's per-tile `collisionRects`** editor (multi-rect → L/U corner shapes). The game reads `manifest.assets[house-walls].tileset.tiles[frame].collisionRects` (`wallCollisionRects`, cached) and creates **one static body per rect** (`addSolid` returns `Sprite[]`; `PlacedObj.bodies`). **FLOOR is a SEPARATE ground layer (`floors` map, 2026-07-21):** the brick/center frame (6 = "window", cycled via R) is marked `solid:false` in the Tileset Editor → it's a **floor**, not a wall. Floors live in their own `floors: Map<key,{sprite,frame}>` (NOT `placed`), render at a low fixed depth (`FLOOR_DEPTH=1.2` — above the grass tilemap, below Cato/walls/furniture), and **can OVERLAP a wall** (one cell can hold both a wall in `placed` AND a floor in `floors`). So a floor placed on the bottom-wall row **tucks UNDER the wall** — the wall draws over its opaque planks, but the wall's transparent top edge reveals the brick, closing the grass gap between floor and wall (the "地板铺到墙上重叠" seamless look, ref image #15). Routing: `isPlacingFloor()` (the held wall material at a non-solid orient) → `placeFloor`/`restoreFloor`/`canPlaceFloor` (allowed on grass OR over a wall; rejects crop/soil/existing-floor); walls → `placeObject`/`canPlaceAt` (empty grass only). Floors are non-colliding so Cato walks on them; hoe-removal digs the FLOOR first (top layer), then a 2nd session the wall under it. Saved in `SaveBlob.floors`. `solid:true` tiles still collide (walls). Rule: **only mark walls solid; leave floor tiles non-solid** (else Cato can't enter — the "地板有碰撞进不去" bug). **Fallback:** frames with no authored collision (+ the door, not a tileset) use `frameSolidRect` — the frame's opaque-pixel bbox (canvas `getImageData`, CORS-clean, cached). **Sync:** the collision lives on the asset record (authored in the UI); it's mirrored into `public/scenes/manifest.json`'s `house-walls` entry (`tileset.tiles`). Editing collision in the UI → re-sync the manifest (pull `asset.tileset` → manifest) for the local preview; a real workspace rebuild regenerates it from the asset record. Seeded once from the wall pixels as a starting point. **Cato needs a small FOOT hitbox (2026-07-21):** his default arcade body is the full **48×48** frame (~3 tiles tall), which wedges against opposite walls inside a small room so arcade physics can't separate him → he **tunnels through walls**. The manifest hitbox (8×4) wasn't applying (asset-id lookup misses on Cato), so `create()` sets it explicitly: `body.setSize(10,7,false).setOffset(19,25)` — a SMALL foot box (10px wide) collides cleanly with the walls AND fits comfortably through the 1-tile (16px) door. **The offset MUST match Cato's feet (depthAnchor y=31 in the 48px frame):** an earlier `offset(19,33)` put the box BELOW his feet, so he penetrated ~8px into walls before it stopped him ("跑到了墙里面"). (This was the "wall collision seems broken" bug.) **Only walls + CLOSED doors are solid** — the floor/interior ground, furniture, and OPEN doors are all non-solid, so Cato can always walk in (never author collision on floor tiles).
- **Depth = standard whole-sprite y-sort (`footY`)** — placed walls/doors/furniture all `setDepth(footY)` (their cell bottom), same as Cato (`applyYSort` → footLine). ## Farming system (2026-07-16/17)
The full loop: **till → plant → water → grow → harvest**, done by the PLAYER (hotbar tools) OR by **Cato on command** (runtime-AI actions).
- **Crops are DATA-DRIVEN (2026-07-22)** — the crop table lives in `public/data/crops.json` (`{ crops: [{ name, label, stages, tall, growWateredSec, growDrySec }] }`), loaded in `BootScene` (`this.load.json` → `applyCropData` in `src/data/crops.ts`) into the live `CROPS`/`CROP_NAMES` refs (built-in fallback if the file is missing/bad). **Per-crop grow times** (`growWateredMs`/`growDryMs`) replaced the old global `CROP_STAGE_MS_*` — each crop matures at its own rate (`updateCrops` reads `CROPS[name]`). `CropName` is now `string`. **This is the first "game data table" — the format a future platform data-table tool would edit (see ADR in umicat-design).** A crop's `name` must still match its atlas frame names (`grow-<name>-<n>` etc.), so new crops need matching art. Assets are the Sprout Lands premium pack, pulled from the **Asset Manager** the real-user way (see "Assets" below).

- **Hotbar + backpack (Stardew model).** `inventory: (ItemStack|null)[]` of `INV_ROWS×INV_COLS` (3×8); **row 0 IS the hotbar** and is seeded with **all the tools + seeds** (hoe, watering-can, 5 seed bags, axe) so touch players reach everything from the bar; harvested crops land in the backpack rows. `HotbarScene` (own scene, native canvas px like CursorScene) draws row 0 from the `inventory` registry key + writes each slot's canvas-px hit-box + a **backpack button** (right screen edge) to `hotbarBounds`; `InventoryScene` draws the full grid when open (**E/I** toggles, Esc closes; **tap the backpack button / tap outside on touch**) + the held stack + writes `inventoryBounds`. **GameScene owns the model + all click logic**; the scenes just render. Number keys 1..N select a hotbar slot (re-press to deselect → empty hand); clicking a slot selects it; backpack cells pick up / drop / merge / swap stacks (Minecraft click-to-pick, click-to-place). Slot art = the region-tagged `inventory` atlas (`frame-medium` panel 9-slice + `slot-dark`/`slot-light` cells, selected = light). Count badge on stacks > 1. World interaction (edge-scroll, camera keys, tilling) is paused while the backpack is open.
- **`ItemStack`** = `{ id, label?, iconKey?, iconFrame?, count, stackable, toolId?, plants? }`. Tools (`toolId: 'hoe'|'watering-can'`) are non-stackable; **seed bags** carry `plants: CropName` (selecting one enters planting mode); harvested crops + seeds stack. `makeSeed`/`makeCrop` build the item stacks; icons from the `farming_plants_items` atlas.
- **Tools & the tile cursor.** The selected item drives a MODE: hoe → till, seed → plant, watering-can → water. `updateTileCursor` (per frame) makes the cursor the **tile bracket + held-tool icon** (not the mouse triangle) whenever a tool is held: **bright + snapped to the tile** when the spot is actionable, **dimmed (gray-tinted bracket + ~40% icon)** when not — the tool never just "vanishes". The real mouse only returns with an empty hand / over the hotbar / in a dialog or backpack. `hoverCell` (the actionable cell) is null when dimmed, so clicks don't act. While a tool-action animation plays (`hoeSwing`/`waterCan`) the cursor is fully hidden — the swinging/pouring tool is the only feedback.
- **Till** (`tillCell`, player) — god-hand hoe swing (`hoeSwingAt`: `tools` sheet `hoe-swing` anim, frames **29→28→27**; `onStrike` fires once via ANIMATION_COMPLETE + delayedCall safety) → the cell flips to soil. **Soil = 4-bit cardinal autotile** (`tilled_autotile.png`, 16 frames, frame = neighbour bitmask N=1/E=2/S=4/W=8; `refreshSoil`/`tilledMask` re-autotile the cell + its 4 neighbours). `tilledCells: Set<"cx,cy">` (idempotent); `tilledSoil: Map<"cx,cy", Image>` holds each soil sprite. Snap/detect via the grass-island `TilemapLayer` (`worldToTileXY`/`tileToWorldXY`/`getTileAtWorldXY`).
- **Un-till (hoe empty dirt → grass, 2026-07-20)** — hoeing an EMPTY tilled cell (no crop) with the hoe *loosens* it: `hoeEmptySoil` swings, and at the strike `loosenCell` shows a **furrow-lines overlay** (`tilled-dirt` frame **47** = tile (3,4) in `tilled_dirt_wide_v2`, transparent except the mark; depth 1.55) + starts a `LOOSEN_WINDOW_MS` (3s) timer. A **second hoe within the window** → `untillCell` digs it back up to **grass** (removes soil + border grass + wetness, dirt-burst, re-autotiles the 4 neighbours, saves). If the timer lapses first → `settleLoosened` drops the furrows and it stays plain dirt. `loosenedCells: Map<key,{overlay,timer}>` holds the transient state (cleared in `applySave`; planting on a loosened cell cancels it). Routed in `actAt` (hoe + tilled + no crop) + the hoe cursor now reads bright on empty soil (`valid = !tilled || !crop || harvestable`). The loosen state is NOT saved (transient); only the resulting till/grass is.
- **Border grass on tilled soil (2026-07-20)** — a plot's EXPOSED edges (sides facing un-tilled ground) grow scattered grass tufts, Sprout-Lands style. `refreshSoilGrass` (called from `refreshSoil`) overlays a grass sprite (`soil-grass` sheet) on each exposed edge with `GRASS_EDGE_CHANCE` (0.55), variant + presence chosen by **`cellHash(cx,cy,salt)`** — deterministic per cell+edge, so it's identical every load (no save needed) and never flickers. `tilledGrass: Map<"cx,cy", Image[]>` holds the overlays (rebuilt each `refreshSoil`, so a newly-tilled neighbour clears the now-interior edge's grass); torn down in `applySave`. Depth 1.6 (above soil 1.5, below y-sorted crops/Cato); untinted (stays green when the soil wet-tints). The `SOIL_EDGES` table maps top/bottom/left/right → `soil-grass` frame indices (the SIDE tiles are reused FLIPPED for the opposite edge). **Asset flow (realistic, in-platform — 2026-07-20):** the source **`tilled_dirt_wide_v2.png`** (Sprout Lands Tilled_Dirt_Wide_v2) is **imported via the Asset Manager** (`POST /projects/{id}/assets`; pull back with the pw-prod token from `cdn.umicat.ai/uploads/{gid}/`) and synced to `public/uploaded/`. The `soil-grass` overlay sheet is then **generated AT RUNTIME in `BootScene.buildSoilGrassSheet`**: copy the 7 grass-edge tiles (coords in the 176×112 sheet — **top×3 at y80 cols 5–7, bottom×2 at y96 cols 5–6, side×2 at col 8 rows 5–6**) onto a `createCanvas` texture, **chroma-key** in-canvas (keep px where `g≥r-6 && g>b+8 && g>90`, else α=0), register the 7 frames. No offline sharp step — upload → load → process is all in game code, so a real user's path works (canvas readback is same-origin, no taint). Frame order = `[t,t,t,b,b,side,side]`, must match `SOIL_EDGES`. (Swapped from the plain `tilled_dirt_v2` — the Wide variant has cleaner square dirt + dedicated side-grass tiles.)
- **Crops** — 5: corn/carrot/tomato/eggplant/pumpkin (`CROPS` table: per-crop stage count; **corn is tall 16×32**, others 16×16). `farming_plants` atlas frames `grow-<crop>-<stage>` (grid-sliced; corn spans 2 rows). `crops: Map<"cx,cy", {name,stage,timer,sprite}>`. Plant on empty tilled soil (`plantCropAt`, base seated at the tile MIDDLE `w.y+TILE/2`, origin bottom, y-sorted by foot like Cato). Grow a stage every `CROP_STAGE_MS_WATERED` (3.5s) on WET soil else `CROP_STAGE_MS_DRY` (12s). **Harvest** a mature crop with the **hoe or empty hand** (NOT watering can / seed — it swings the hoe): the produce pops OUT of the ground in a cute arc (`playHarvestPop` — semicircle to a random side + landing bounce + size wobble), banked to the inventory.
- **Watering = wet the SOIL, not the crop.** Wetness lives on the **cell** (`soilWet: Map<"cx,cy", ms>`, counted down in `updateSoil`), so **any tilled cell can be watered** — crop or not, wet or not (re-watering just refreshes). Wet soil is **tinted** (`WET_SOIL_TINT`, no wet tile exists in the dirt set) for `WET_DURATION_MS` (9s) and any crop on it grows fast. `waterCropAt` sets it + plays the splash; the **player** path (`playerWater`) adds a **god-hand watering-can pour** (`water-pour` anim, `tools` frames 0→1; positioned so the LEFT spout is over the crop). Splash art isn't centred in its 48px frame — offset applied so it lands on the tile.

## Cato behaviors (runtime-AI `do` actions, ADR-017/018)
Cato is `umicat.ai.npc({ playbook:'cato', actions:[…] })`. `say()` returns `r.do: AiActionCall[]`; `runCatoActions` dispatches. A single `catoTask` (`type: 'till'|'plant'|'water'|'harvest'|'chop'|'fruit'|'mine'|'bush'|'forage'`, a cell queue + per-cell cooldown + `stand`) drives a walk-to-cell state machine in `update()` that OVERRIDES the wander. For each target Cato stands on an ADJACENT cell (`computeStand`, prefers on-island) facing it, plays his own body animation (**`axe-<dir>` for chop/fruit**, **`water-<dir>` for water**, else **`attack-<dir>`** hoe-swing for till/plant/harvest/mine/bush/forage), and the effect lands mid-swing (`CATO_TILL_STRIKE_MS`). Player = god-hand tool sprites; **Cato = his own body animations**. The `axe-<dir>` frames (128–159 in `premium_character_spritesheet`) were the old `hurt-*` slots — the user re-tagged them `axe-*` in the Asset Manager sprite editor; I matched that in `public/scenes/manifest.json` (rename, same frame ranges — `hurt-*` was unused). **Regression fixed same day:** `updatePlayerMovement` (PLAYER_CONTROL) ran every frame and stamped `idle-<dir>` over the strike anim during the per-hit cooldown (the swing showed for ~1 frame then Cato looked like he was just standing there) — guard `if (this.catoTask) return` at its top so the task fully owns Cato. This had silently broken the till/attack swing too since PLAYER_CONTROL landed.
- **Crop actions:** **`till_plot`** (nearest N×N open grass), **`plant_crop`**, **`water_crops`**, **`harvest_crops`**. Chaining "till→plant→water" works for "grow me corn".
- **Wild-world actions (2026-07-23):** **`chop_trees`** (fell trees — a fruit tree drops fruit then falls), **`harvest_fruit`** (shake fruit off, leave the tree standing), **`mine_stones`** (knock big stones until mined out + broken), **`harvest_bushes`** (pick ripe berry bushes), **`forage`** (gather mature mushrooms/flowers/grass/small-stones). Each `startXxxTask` finds targets via `nearestCells(keys, count)` over the object Map (`trees`/`bigStones`/`bushes`/`foragables`) and Cato's strike calls the SAME **direct-effect** fn the player's tool uses (`onChopStrike`/`onKnockStrike`/`reapBush`/`reapForagable`) — NOT the god-hand-swing wrapper.
- **Single- vs multi-strike:** bush/forage/crops finish a target in ONE hit → advance. **chop/fruit/mine keep re-hitting the SAME target** (Cato stays put) until it self-invalidates (`taskCellValid`: tree felled / de-fruited / stone broken), then drops it; a `strikes>=20` cap backstops any target that never clears.
- **A\* pathfinding (2026-07-23):** task movement routes Cato AROUND obstacles instead of walking straight at the target. Per target, `planStand` picks the nearest **reachable** walkable adjacent stand cell (tries each side, `findPath` to each) and caches the A\* route (`task.path`, world-centre waypoints); `updateCatoTask` walks them one tile at a time (`walkCardinalToward` between consecutive walkable cells = clean cardinal steps). `isWalkableCell` = on-island (`getTileAt`≠null, not `tile.collides`) AND no tree/big-stone/wall/window/closed-door on it (mirrors the wallGroup colliders exactly; bushes/crops/foragables are passable). 4-connected (no diagonal walk anim) → naturally L-shaped/staircase routes. If NO side is reachable, the target is skipped immediately (no more pushing into a wall). Verified via Playwright: tree wall between Cato and a bush → he detoured (`31,9`→col `29`→`31,6`) and reaped it. **Was** the cardinal-straight-line `walkCardinalToward` + a 2.2s "stall-skip" band-aid (`vel=[-60,0]` frozen-in-wall bug) — A\* replaces the guessing; the stall check survives only as a backstop for a DYNAMIC block (wall placed mid-walk). **Caveat:** big-stone colliders are 22×10 (wider than a 16px tile) so they overhang neighbour cells — Cato can wedge squeezing right past one; rare (stones are sparse), the stall backstop catches it. Wander/leash still use plain `walkCardinalToward` (short strolls, not worth pathing).
- **Observation:** `buildObservation` includes a `wild` block (`trees`, `treesWithFruit`, `bigStones`, `ripeBushes`, `matureForageables`) so Cato can answer "are there trees to chop?" + proactively suggest. Debug keys: **C**=chop, **F**=fruit, **N**=mine, **J**=bush, **K**=forage (like T/P/O/H for crops).
- **Gotchas that made it work** (see memory `cato-do-action-first-wiring`): the task must NOT freeze while the dialog is open (it was — fixed) + auto-close the dialog after dispatch so Cato walks off; the playbook MUST say "call the action, don't just narrate it" (Haiku echoed the stock line without emitting the tool call); Cato stands beside + faces the target so the swing matches where the effect lands.
- **Backend**: game-manager `RuntimeAiService` already compiles `actions`→Anthropic tools + parses `tool_use`→`do` (default Haiku). No backend change needed.

## Input — mouse + touch (2026-07-17/18)
- **Unified routing:** `actAt(x, y)` (canvas px) is the ONE click/tap router — it computes the target tile from the point (NOT the hover cursor), so it works for both mouse and touch: **backpack (if `inventoryOpen`, cell pick/drop or click-outside-to-close, returns first)** → build palette → backpack button → hotbar slot → over-bar swallow → world tile (harvest/till/plant/water by the held tool) → portrait/cat/camera. `handleLockedClick` calls it with the virtual cursor; touch calls it with the real tap px.
- **Backpack must swallow the click even when UNLOCKED (2026-07-23):** the mouse `pointerdown` handler routes through `actAt` only when `locked`; pointer lock is dropped after chatting (`openDialog`→`exitPointerLock`) and not re-taken, so an open backpack is commonly UNLOCKED — where the handler used to skip `actAt` and hit the `catContains → openDialog` branch, opening the chat for **Cato sitting behind the panel** instead of clicking the cell. Fix: an `if (this.inventoryOpen) { locked ? handleLockedClick() : actAt(pointer.x, pointer.y); return; }` guard right after the `dialogOpen` check, so a backpack click always reaches `actAt` (which handles the cell + returns) and never falls through to the world. Verified via a synthetic `pointerdown` on Cato's body with backpack-open+unlocked → dialog stayed closed.
- **Mouse (desktop):** click captures the pointer (lock), a virtual cursor (`vcursor`) is driven by relative deltas; `updateTileCursor` shows the bright/dim tool bracket on hover.
- **Touch:** never locks. A **tap** (pointerup, <12px move; a bigger drag is the Rex-Pan camera pan) → `actAt(tap)`. In the **open backpack**, a touch **press-drag-release** moves a stack (`endInventoryTouch`/`invDragFrom`): press a cell picks it up (it follows the finger — the touch handlers set `cursorState`, and **`update()` only drives `cursorState` from `vcursor` while LOCKED** or the two fight → a flickering ghost), drag, release on a cell to drop/merge/swap; the dragged stack renders ABOVE the finger. No hover preview on touch (that's fine — the hotbar highlight shows the selected tool).

## Movement / camera (2026-07-17; player-control 2026-07-21)
- **PLAYER CONTROL (`PLAYER_CONTROL=true`, 2026-07-21):** WASD / arrows now **drive Cato directly** (`updatePlayerMovement`: 8-dir velocity at `PLAYER_SPEED`, facing by dominant axis since there's no diagonal walk anim; frozen while chatting/backpack) and the **camera follows him** (`cameraFollow` forced true; edge-scroll auto-disables when following). Wall collision stops him. Cato's **chat-commanded tasks** (till/plant/…) still run and take priority. **RUNTIME-TOGGLEABLE now (2026-07-26):** `PLAYER_CONTROL` is instance state `this.playerControl` (the const `PLAYER_CONTROL_DEFAULT` is just the starting mode, currently **false** = AI companion). An **on-screen TEST button** (`createControlToggle`, a DOM `<button>` top-centre; removed on scene shutdown) flips it (`setControlMode`: Cato mode → `cameraFollow` on; camera mode → free pan + stop Cato's velocity). Test-only — remove before release. On desktop under pointer lock press Esc first to click the DOM button; touch works directly.
- **AI-companion mode (`PLAYER_CONTROL=false`):** WASD / arrows pan the CAMERA (`updateCameraKeys`); Cato roams on his own. Mouse **edge-scroll** (pointer-locked only) + **touch drag** (Rex Pan) also pan; a pan releases camera-follow + is blocked behind a modal.
- **Clicking Cato's top-right portrait → `focusCato`** (2026-07-20): aims the camera at him (`followCato`) AND opens the chat (`openDialog`) in one gesture. **Wiring is subtle** — the portrait is a HUD `icon-button` (`name:'photo-frame'`) living in the SEPARATE **`UmicatHud` scene** (rendered ABOVE GameScene), which **swallows the pointer** before any GameScene object sees it (no GameScene `pointerdown`/`findCatHit` handler fires). So the click is caught via the HUD scene's own **`hud:press`** event (`game.scene.getScene('UmicatHud').events.on('hud:press', (id, entity) => entity.name==='photo-frame' && focusCato())`) — fires on pointer-up for mouse+touch when NOT pointer-locked. The pointer-**locked** mouse case can't reach the HUD (frozen cursor), so it goes through `actAt`'s `findCatBounds` check instead. `findCatHit` is now only the hover/`overUi` + hand-cursor rect.
- **Camera follow = EXACT, in POST_UPDATE, + variable-step physics (2026-07-21):** the "walking shake" fix is TWO changes that only work together — took several wrong turns to land (all Playwright-measured):
  1. **`physics.world.fixedStep = false`** (set in `create`). Phaser's default fixed-step accumulator runs 0/1/2 physics steps per render frame, so Cato's per-frame movement is uneven → micro-stutter. Variable step advances him by the REAL frame time each frame → smooth motion (he's slow, no tunnelling).
  2. **`updateCameraFollow` = EXACT follow** — `cam.scrollX = child.x − w/2` (origin-0.5 form), registered on `Phaser.Scenes.Events.POST_UPDATE` (NOT `update()`, which runs BEFORE Arcade syncs `child.x` → a stale, one-step-behind position). This pixel-locks Cato to screen centre (`child.x−scrollX` = constant 600 → measured **0px** on-screen sway); the world scrolls under him at the now-smooth physics rate.
  - **Wrong turns (don't repeat):** a per-frame follow **lerp** was in the original code — it oscillates ±~11px in response to frame-timing variance (measured), i.e. the lerp itself WAS most of the shake — **removed it.** Exact-follow with `fixedStep:true` looks worse still (Cato locked but the world judders from the accumulator, worst in the scroll direction) — that combo is the trap; you need BOTH changes. RE-CENTRING (portrait double-tap) is the one-shot `snapToChild()` tween; `updateCameraFollow` skips itself while a camera tween runs so it isn't fought.
- **Cato is LEASHED to the camera centre** (`wanderLeashRadius` — sized to the visible area so he keeps in frame at any zoom; hysteresis via `catoReturning`): he stays near the view centre like a companion, walks back if he strays, and returns to centre after a task.
- **Wander = calm "rest, occasionally amble to a point of interest" (2026-07-20)**, NOT random walk/idle. Cato mostly RESTS (`startWanderIdle`, `REST_MIN/MAX_MS` 3–7s); when a rest ends he *sometimes* (`WANDER_MOVE_CHANCE`) strolls to a nearby **POI** — a planted crop or a world prop (`pickWanderTarget` scans `this.crops` + `this.ySortSprites` within the leash) — stops ~a tile short (`WANDER_ARRIVE`) and rests FACING it (`faceTargetPoint`, "has a look"). If nothing's in reach he only occasionally ambles to a random nearby spot (`randomStrollPoint`, `WANDER_STROLL_CHANCE`). Freezes while chatting. (Old random-direction `startWanderWalk`/`WALK_DIRS` removed.)
- **Cato only moves CARDINALLY** — the sheet has no diagonal walk. `walkCardinalToward` moves along one axis at a time → L-shaped path, used by the leash return, the POI amble, AND task movement. **AXIS HYSTERESIS** (2026-07-20): it commits to the axis it's already walking until that axis is aligned before switching — without this, when dx≈dy the "dominant axis" flipped every frame → a fast left/right **wobble** (the bug that prompted this). Verified 0 rapid flips over 45s via Playwright.

## Weather / time-of-day / money HUD (top-left, 2026-07-24)
A screen-fixed native-px widget in its OWN scene **`WeatherScene`** (registered in main.ts, launched from `setupPointerLock` like HotbarScene — separate scene = unzoomed/unscrolled by the world camera). GameScene owns the MODEL + publishes it to registry `weatherHud` (`{visible, bgFrame, weatherFrame, pointerStep, money, rev}`); the scene re-renders on `changedata-weatherHud`. Layout: LEFT window = time-tinted background + weather icon; RIGHT window = time dial (`time-bg`) + sun-arc **pointer**; then a connected coin bar. Everything is at **`S=1.5`** and every size/offset is `S`-relative (consts at the top of `WeatherScene`) — retune the whole widget by changing `S`. `weather-frame-big` at S=3 → 276px was "too big"; landed on the big frame (nicer + a finer 5-step pointer) at S=1.5 (non-integer → slightly soft pixels, accepted). A `*-small` set is also tagged if wanted.
- **Weather window = TWO layers.** The icons have a HUGE transparent margin (content is only ~34×34 inside the 48×48 frame), so `displaySize` is scaled UP to make the *content* fill the ~34px window (naïvely fitting the 48px frame left a big gap — the bug in the first cut). `bgFrame` (`background-morning|noon|night`, time-tinted) is display-sized ~50×S to fill; the transparent `weatherFrame` (`*-no-bg`, e.g. `sunny-no-bg`) is ~40×S centred on top. Weather is sunny-only decorative (`WEATHER_ICONS` cycles the 3 sunny `-no-bg` variants per day); the BACKGROUND changes with time (`WEATHER_BGS` by `bgIndex()` 0..2).
- **Pointer pivots on the divider BUMP, not the window centre.** `arrow-big-1..5` are cropped tight, so each frame's knob (tail) sits at a different spot — anchoring by `origin 0.5` made the tail wander for the up/down arrows. Fix: the bump centre is frame native **(53,25)** (`PIVOT`), and each arrow is anchored by its own knob (`ARROW_ORIGINS`, found via a pixel scan: thickest+farthest-from-centroid point) so the tail stays put while the tip sweeps ↗→↘.
- **Coin bar** (`balance-frame-big`, nine-slice so it fits any number): TOP-aligned to the frame + left edge TUCKED behind the frame (drawn before the frame → its border/leaf overlaps → reads connected). The coin (`coin-white-border-shadow-below`) is a small vertical coin with lots of padding (content 7×10 in 16×16) → displayed at `20×S` (28×S overflowed the 24×S-tall bar — the white border poked out). Money is **right-aligned** (`origin(1,0.5)` at the bar's right end).
- **Systems (all NEW — none existed):** `money` (`addMoney` is the single choke-point; a real buy/sell economy runs on it now — see "Order book + buy/sell economy"), `dayTimeMs`/`dayCount` (a day loops every `DAY_LEN_MS`=10min; `updateDayClock` advances it in update() + republishes only when `pointerStep()` (1..5) or `bgIndex()` (0..2) flips). `buildObservation.timeOfDay` derives from `pointerStep()`. All in **SaveBlob v6** (money/dayTimeMs/dayCount; older saves default 0). Debug keys **Y** = +12345 coins, **U** = jump the clock one pointer step.
- **Assets** (Asset-Manager-tagged, synced to `public/uploaded/` + atlas JSON built from the regions in BootScene): `weather-ui` (frame/bar/dial/arrows — big AND small variants), `weather-icons` (`background-*` + `*-no-bg` icons + old with-bg ones), `coins`. **Can't screenshot the HUD headlessly** (preview WebGL renders black) — so all LAYOUT was tuned with `sharp` mockups (composite the atlas regions at native px, upscale, eyeball) and only the WIRING verified via `__game`. Re-tuning = mock in sharp, then set the `S`-relative consts.

## Scripted dialogue system — intro/cutscenes (P1, 2026-08-03)
A SECOND, complementary dialogue mode alongside the runtime-AI free chat: **authored, non-AI, deterministic** node-graph dialogue for cutscenes / intros / tutorials (like Ink/Yarn/Twine). The new-game **intro** greets the player, introduces the island, and points out the tools. Design decisions (from the user): **all hand-written lines** (i18n, zero LLM at runtime), a future **standalone visual node-graph editor app** (`Dialogue Manager`, P2), and tutorial spotlights are **highlight-only (no gating)**. This is the platform's 4th content layer (Documents=design · Playbooks=AI behavior · Data Tables=numbers · **Dialogue=scripted narrative**) — built game-side first, to be generalized into an SDK primitive `umicat.dialogue` + the tool later.
- **Data = a node graph** in `public/dialogue/*.json` (the shared contract for runner/game/tool): `{ id, trigger, start, nodes }`. Node types (`src/dialogue.ts`): `line` (speaker/emote/i18n text/spotlight/next), `choice` (branch — **type+runner done, no UI yet in P1** so the intro is linear), `set`/`if` (flag branch memory), `end`. `LangText` = string | `{ en, 'zh-CN' }`, resolved by `trDialogue(text, getLang())`.
- **Portable core** `src/dialogue.ts` (no Phaser): `DialogueRunner` walks the graph and calls a `DialogueHost` (showLine/showChoices/getFlag/setFlag/finish) — deliberately host-agnostic so it lifts into the SDK primitive unchanged.
- **GameScene = the host**: `startDialogue(id)` builds a runner from the JSON cache; `dialogueShowLine` REUSES the existing chat box in **CUTSCENE mode** — `openDialog(seed, cutscene=true)` shows the box + portrait + name but **filters out the text-INPUT widgets** (`chat-input`/`chat-input-field`; KEEP `chat-text`, the text-area bound to `catoDialogText` — filtering it = an empty box, the bug hit first) and **keeps the hotbar VISIBLE** (`publishInventory`/hotbar-visible gate read `this.cutscene`) so tool spotlights land on it. Advancing (tap/space) routes through `advanceCutscene` (reveal/next-page → next node → `finish`); Esc is disabled during a cutscene. `{name}` → the signed-in player's name or a `friend`/`朋友` fallback (standalone).
- **Spotlight = `DialogueScene`** (new native-px overlay, launched + `bringToTop`'d with the HUD): a **non-interactive** pulsing gold ring (NO full-screen dim → never eats the advance taps) around a target rect from registry `dialogueSpotlight`. `spotlightRect('hotbar:<toolId>' | 'hotbar:seed')` resolves the target to a hotbar slot via `hotbarBounds.slots` (by `toolId`, or any seed bag via `.plants`).

## Cato dialog (2026-06-29, SDK 1.0.27+)
**`catContains` = PER-PIXEL alpha, not the frame box (2026-07-23):** Cato fills only a small patch of his 48×48 frame (foot box at frame-local 19,25) — the rest is transparent padding — so `getBounds().contains` triggered the chat from far away over the padding. Now it maps the world point to a texel of the CURRENT frame (honouring origin/scale/`flipX`) and tests `textures.getPixelAlpha(...) > 16`; falls back to the box only if the texture is unreadable (`getPixelAlpha` returns null — but it IS readable in the deployed WebGL build, verified: a 12×12 grid over the box went from 144/144 hits to ~10/144, tight on the visible cat, corners now miss). Same padding trap applies to any pixel-art sprite hit-test — the tree/stone/foragable pickers use `getBounds().contains` too and could be tightened the same way if far-clicks bother there.

Provided ONLY when the game runs EMBEDDED through the platform; the raw preview URL is `standalone` → `user:null` → falls back to the playbook's "guardian"/"you". So verify the name in a real platform play session, not the direct preview link. Opening releases pointer lock but swaps the canvas CSS cursor to the pixel triangle; `updateEdgeScroll`/camera keys early-return while `dialogOpen`. Pixel font `zpix.woff2` via `fonts.json`, 24px.
- **RPG typewriter + pagination (2026-07-20):** Cato's reply reveals **char-by-char** (`showDialogText`→`startTypingPage`, a `time.addEvent` per-char `TYPE_MS=50` — cozy pace), and text that overflows the box is **paginated** (`paginate` — a hidden design-sized measuring div, `measureEl`, binary-searches the largest prefix whose rendered height ≤ `DIALOG_FIT_H`; wrapping is scale-invariant so design-scale measuring is exact). **No scroll**: when a page is full and more remain, a **"more" arrow** shows bottom-right of the box (`cato-more-icon` HUD image, `all_icons` atlas frame `play-brown` — a TAN triangle, so it's **tinted dark** `#3f2c18` or it's invisible on the tan box; alpha-pulses). **Advance** = click anywhere (incl. ON the box, see click-through below) / Space (guarded so it doesn't fire while the chat input is focused) / tap → `advanceDialog()`: snap the typing page complete, else next page; returns false when all shown so the same gesture then **closes** the dialog. Greetings / "thinking…" / error lines use `setImmediateDialog` (instant, one page, resets pagination).
  - **Box is deliberately short** — `chat-message` + `cato-dialog-text` are **700×130** (~2 lines; small so normal replies paginate), `DIALOG_FIT_H=118` (box − margin for the arrow + font rounding). `cato-dialog-text` uses **`align:start`** (start-of-line per language — left for LTR, right for RTL — NOT centered). The box BOTTOM is anchored (`offsetY -60`, origin bottom), so it shrinks from the TOP: the more-arrow (anchored to the box bottom) needs no change on a resize, but the **portrait + name frame must move with the box TOP** (they sit just above it — `cato-portrait -191`, `cato-name-frame`/`-text -192` for the 130-tall box; retune both if you change the height).
  - **Click-through fix (`makeDialogTextClickThrough`, called on open):** the SDK renders `text-area` widgets as DOM `<div>` overlays with `pointer-events:auto` (z-index **99980**), which SWALLOW clicks landing ON the box — so advancing only worked clicking OUTSIDE (where the click reaches the canvas). These divs are display-only, so we set them `pointer-events:none`; clicks then fall to the canvas and `advanceDialog` fires. The chat-input-field (text-**input**, z-index **99990**) keeps its pointer events so the player can still click it to type.
  - Assets: `public/uploaded/all_icons.{png,json}` (hand-authored atlas-json, one region `play-brown` at 144,48 16×16) + a manifest `assets[]` entry. Dev key **M** shows a long multi-page reply to exercise it without the AI.
  - **First-render gotcha (`catoDialogText` pre-seed):** Phaser's DataManager emits `setdata` (not `changedata`) on a key's FIRST set, and the SDK text-area only listens for `changedata-<binding>`. So the very first `registry.set('catoDialogText', …)` (the open greeting) silently stayed on the "…" fallback. Fixed by pre-seeding `registry.set('catoDialogText','')` once at scene setup (in `buildFindCatButton`) so every real line is a `changedata`.
- **Game-state awareness (2026-07-18):** each turn `submitDialog` sends `buildObservation()` as the `observation` — the **backpack** (items aggregated by name + counts) + a **farm** summary (crops by type, ripe / growing / thirsty counts, empty tilled soil). So Cato can answer "what seeds do we have / anything ripe / room to plant" and act sensibly (don't offer a crop whose seeds aren't in the bag). This is the **cheap state-injection layer BEFORE a real tool-agent** — the SDK `Npc` already keeps + sends conversation history, and the game holds all state locally, so we just hand it over. **Roadmap** (see memory / the design discussion): recipes into the observation when a crafting system lands; a client-orchestrated query-tool **agent loop** when lookups get large; **persistent per-player NPC memory** (ADR-019, a `summary` + pinned `facts` store consolidated by a Haiku call) is a SEPARATE axis, deferred until the game systems are built out.

## Save data — auto-save + restore (2026-07-18)
Persists the whole game per (game, user) with the platform primitive **`umicat.saves`** (signed-in → backend via home-ui `useUmicatRpcHost` → game-manager `GameSaveService`; anonymous/standalone → localStorage `umicat:saves:standalone:state` — no auth branching in game code). Key `state`.
- **What:** `buildSave`/`applySave` (blob `v:1`) serialize the backpack (`{id,count}` → `itemFromId` rebuilds full stacks — the single factory, also used by `setupInventory`), hotbar selection, `tilled` cells, per-cell `soilWet` (remaining ms), crops (`{key,name,stage,timer}`), and Cato's position. `restoreCrop` rebuilds crop sprites at their stage; soil is re-autotiled after all tilled cells load. **v1 does NOT simulate offline growth** — timers restore as-saved.
- **Auto-save:** `scheduleSave()` debounces **700ms** after any mutation — hooked into `publishInventory` (covers inventory + selection) + till / plant / water / Cato-till / crop stage-advance. Plus a 15s periodic backstop + a save on tab hide / `pagehide`. Short debounce is deliberate: the backend write is async and a save-on-**close** can't flush as the page tears down, so the state must reach the backend **while the tab is open**.
- **Never wipe the save — two guards (both bugs were hit):** (1) **`saveArmed`** — saving is armed ONLY after `loadGame` has actually READ the store (found or empty); a slow load or read error leaves it disarmed, so the default state can never overwrite the real save before it's restored. (2) The world + hotbar are **hidden behind a "Loading…" cover** (`showLoadingCover`/`markReady`, `gameReady` flag) until the save is applied — no flash of the empty farm; an 8s fallback + the init-failure path always reveal. (Also: do NOT bind destructive dev keys like a bare `saves.delete` — a stray K press wiped saves.)

## World / camera plumbing (stable)
- Scene-as-data: `water` + `grass-island` tilemap layers; world 1280×720; camera bounds = the **water** tilemap extent (`camera.bounds: { fitTo }` in `main.json`) so you can't pan past the ocean. **RESIZE mode + adaptive integer zoom** (`computeZoom`, `referenceZoom: DESIGN_ZOOM=3`); pin origin via `originTopLeftScroll` — never `setOrigin(0,0)` (breaks tilemap culling).
- **Resolve tilemaps by NAME** (`'island'`/`'water'`), not hardcoded id — re-dragging changes the id and silently breaks colliders / camera `fitTo` (bit us twice). Collision via `addTilemapCollider` + `applyAssetHitbox`.
- **Pointer lock + custom cursor**: click captures the mouse, Esc releases; a VIRTUAL cursor (`vcursor`) driven by relative deltas, clamped to canvas; `handleLockedClick` routes clicks (hotbar → backpack → farming → portrait → cat → camera-release). Cursor rendered in `CursorScene` (top overlay). Editor iframe needs `allow="pointer-lock"` + `sandbox="allow-pointer-lock"` (home-ui `GameDetail.tsx`).
