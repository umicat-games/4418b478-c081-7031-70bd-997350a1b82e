# Catopia — Technical Session Notes

## What game is this?
**Title**: Catopia
**Genre**: Nurturing / Social / Simulation / Farming
**Core mechanic**: The player guards **Cato**, an AI-driven island spirit (a cat). Cato has autonomous behavior (algorithmic wander) AND runtime-AI conversation + **actions** (he can be asked, in chat, to farm). The player also farms directly (hoe / seeds / watering can via a hotbar). Bond = **guardian ↔ guarded spirit** (Pokémon-like, NOT parent/child).

## Farming system (2026-07-16/17)
The full loop: **till → plant → water → grow → harvest**, done by the PLAYER (hotbar tools) OR by **Cato on command** (runtime-AI actions). Assets are the Sprout Lands premium pack, pulled from the **Asset Manager** the real-user way (see "Assets" below).

- **Hotbar + backpack (Stardew model).** `inventory: (ItemStack|null)[]` of `INV_ROWS×INV_COLS` (3×8); **row 0 IS the hotbar** and is seeded with **all the tools + seeds** (hoe, watering-can, 5 seed bags, axe) so touch players reach everything from the bar; harvested crops land in the backpack rows. `HotbarScene` (own scene, native canvas px like CursorScene) draws row 0 from the `inventory` registry key + writes each slot's canvas-px hit-box + a **backpack button** (right screen edge) to `hotbarBounds`; `InventoryScene` draws the full grid when open (**E/I** toggles, Esc closes; **tap the backpack button / tap outside on touch**) + the held stack + writes `inventoryBounds`. **GameScene owns the model + all click logic**; the scenes just render. Number keys 1..N select a hotbar slot (re-press to deselect → empty hand); clicking a slot selects it; backpack cells pick up / drop / merge / swap stacks (Minecraft click-to-pick, click-to-place). Slot art = the region-tagged `inventory` atlas (`frame-medium` panel 9-slice + `slot-dark`/`slot-light` cells, selected = light). Count badge on stacks > 1. World interaction (edge-scroll, camera keys, tilling) is paused while the backpack is open.
- **`ItemStack`** = `{ id, label?, iconKey?, iconFrame?, count, stackable, toolId?, plants? }`. Tools (`toolId: 'hoe'|'watering-can'`) are non-stackable; **seed bags** carry `plants: CropName` (selecting one enters planting mode); harvested crops + seeds stack. `makeSeed`/`makeCrop` build the item stacks; icons from the `farming_plants_items` atlas.
- **Tools & the tile cursor.** The selected item drives a MODE: hoe → till, seed → plant, watering-can → water. `updateTileCursor` (per frame) makes the cursor the **tile bracket + held-tool icon** (not the mouse triangle) whenever a tool is held: **bright + snapped to the tile** when the spot is actionable, **dimmed (gray-tinted bracket + ~40% icon)** when not — the tool never just "vanishes". The real mouse only returns with an empty hand / over the hotbar / in a dialog or backpack. `hoverCell` (the actionable cell) is null when dimmed, so clicks don't act. While a tool-action animation plays (`hoeSwing`/`waterCan`) the cursor is fully hidden — the swinging/pouring tool is the only feedback.
- **Till** (`tillCell`, player) — god-hand hoe swing (`hoeSwingAt`: `tools` sheet `hoe-swing` anim, frames **29→28→27**; `onStrike` fires once via ANIMATION_COMPLETE + delayedCall safety) → the cell flips to soil. **Soil = 4-bit cardinal autotile** (`tilled_autotile.png`, 16 frames, frame = neighbour bitmask N=1/E=2/S=4/W=8; `refreshSoil`/`tilledMask` re-autotile the cell + its 4 neighbours). `tilledCells: Set<"cx,cy">` (idempotent); `tilledSoil: Map<"cx,cy", Image>` holds each soil sprite. Snap/detect via the grass-island `TilemapLayer` (`worldToTileXY`/`tileToWorldXY`/`getTileAtWorldXY`).
- **Crops** — 5: corn/carrot/tomato/eggplant/pumpkin (`CROPS` table: per-crop stage count; **corn is tall 16×32**, others 16×16). `farming_plants` atlas frames `grow-<crop>-<stage>` (grid-sliced; corn spans 2 rows). `crops: Map<"cx,cy", {name,stage,timer,sprite}>`. Plant on empty tilled soil (`plantCropAt`, base seated at the tile MIDDLE `w.y+TILE/2`, origin bottom, y-sorted by foot like Cato). Grow a stage every `CROP_STAGE_MS_WATERED` (3.5s) on WET soil else `CROP_STAGE_MS_DRY` (12s). **Harvest** a mature crop with the **hoe or empty hand** (NOT watering can / seed — it swings the hoe): the produce pops OUT of the ground in a cute arc (`playHarvestPop` — semicircle to a random side + landing bounce + size wobble), banked to the inventory.
- **Watering = wet the SOIL, not the crop.** Wetness lives on the **cell** (`soilWet: Map<"cx,cy", ms>`, counted down in `updateSoil`), so **any tilled cell can be watered** — crop or not, wet or not (re-watering just refreshes). Wet soil is **tinted** (`WET_SOIL_TINT`, no wet tile exists in the dirt set) for `WET_DURATION_MS` (9s) and any crop on it grows fast. `waterCropAt` sets it + plays the splash; the **player** path (`playerWater`) adds a **god-hand watering-can pour** (`water-pour` anim, `tools` frames 0→1; positioned so the LEFT spout is over the crop). Splash art isn't centred in its 48px frame — offset applied so it lands on the tile.

## Cato behaviors (runtime-AI `do` actions, ADR-017/018)
Cato is `umicat.ai.npc({ playbook:'cato', actions:[…] })`. `say()` returns `r.do: AiActionCall[]`; `runCatoActions` dispatches. A single `catoTask` (`type: 'till'|'plant'|'water'`, a cell queue + per-cell cooldown + `stand`) drives a walk-to-cell state machine in `update()` that OVERRIDES the wander. For each target Cato stands on an ADJACENT cell (`computeStand`, prefers on-island) facing it, plays his own animation (`attack-<dir>` for till/plant, **`water-<dir>` for water**), and the effect lands mid-swing (`CATO_TILL_STRIKE_MS`). Player = god-hand tools; **Cato = his own body animations** (the hoe/watering split mirrors this).
- Actions: **`till_plot`** (find nearest N×N open grass, hoe it), **`plant_crop`** (sow nearest empty soil with a crop), **`water_crops`** (water nearest growing crops on dry soil). All declared on the npc + taught in `public/playbooks/cato.md`; chaining "till→plant→water" works for "grow me corn".
- **Gotchas that made it work** (see memory `cato-do-action-first-wiring`): the task must NOT freeze while the dialog is open (it was — fixed) + auto-close the dialog after dispatch so Cato walks off; the playbook MUST say "call the action, don't just narrate it" (Haiku echoed the stock line without emitting the tool call); Cato stands beside + faces the target so the swing matches where the effect lands.
- **Backend**: game-manager `RuntimeAiService` already compiles `actions`→Anthropic tools + parses `tool_use`→`do` (default Haiku). No backend change needed.

## Input — mouse + touch (2026-07-17/18)
- **Unified routing:** `actAt(x, y)` (canvas px) is the ONE click/tap router — it computes the target tile from the point (NOT the hover cursor), so it works for both mouse and touch: backpack button → hotbar slot → over-bar swallow → world tile (harvest/till/plant/water by the held tool) → portrait/cat/camera. `handleLockedClick` calls it with the virtual cursor; touch calls it with the real tap px.
- **Mouse (desktop):** click captures the pointer (lock), a virtual cursor (`vcursor`) is driven by relative deltas; `updateTileCursor` shows the bright/dim tool bracket on hover.
- **Touch:** never locks. A **tap** (pointerup, <12px move; a bigger drag is the Rex-Pan camera pan) → `actAt(tap)`. In the **open backpack**, a touch **press-drag-release** moves a stack (`endInventoryTouch`/`invDragFrom`): press a cell picks it up (it follows the finger — the touch handlers set `cursorState`, and **`update()` only drives `cursorState` from `vcursor` while LOCKED** or the two fight → a flickering ghost), drag, release on a cell to drop/merge/swap; the dragged stack renders ABOVE the finger. No hover preview on touch (that's fine — the hotbar highlight shows the selected tool).

## Movement / camera (2026-07-17)
- **WASD / arrows pan the CAMERA** (`updateCameraKeys`); Cato roams on his own (no direct player control — the old `PLAYER_CONTROL` path is gone). Mouse **edge-scroll** (pointer-locked only) + **touch drag** (Rex Pan) also pan; a pan releases camera-follow + is blocked behind a modal.
- **Clicking Cato's top-right portrait → `focusCato`** (2026-07-20): aims the camera at him (`followCato`) AND opens the chat (`openDialog`) in one gesture. **Wiring is subtle** — the portrait is a HUD `icon-button` (`name:'photo-frame'`) living in the SEPARATE **`UmicatHud` scene** (rendered ABOVE GameScene), which **swallows the pointer** before any GameScene object sees it (no GameScene `pointerdown`/`findCatHit` handler fires). So the click is caught via the HUD scene's own **`hud:press`** event (`game.scene.getScene('UmicatHud').events.on('hud:press', (id, entity) => entity.name==='photo-frame' && focusCato())`) — fires on pointer-up for mouse+touch when NOT pointer-locked. The pointer-**locked** mouse case can't reach the HUD (frozen cursor), so it goes through `actAt`'s `findCatBounds` check instead. `findCatHit` is now only the hover/`overUi` + hand-cursor rect.
- **Cato is LEASHED to the camera centre** (`CATO_LEASH_RADIUS`/`RETURN`, hysteresis via `catoReturning`): he wanders near the view centre like a companion, walks back if he strays, and returns to centre after a task. Wander = walk-stop-walk (`startWanderWalk`/`startWanderIdle`, freezes while chatting).
- **Cato only moves CARDINALLY** — the sheet has no diagonal walk. `walkCardinalToward` moves along one axis at a time (dominant first → L-shaped path), used by the leash return AND task movement.

## Cato dialog (2026-06-29, SDK 1.0.27+)
Click the cat (`catContains`) → chat HUD widgets slide up (`chat-message`/`chat-input`/`chat-text`/`chat-input-field`, authored `visible:false`; `text-input` + `text-area` widgets, SDK 1.0.28/29) → type + Enter → Cato replies (LLM, player pays credits, needs sign-in). Personality in `public/playbooks/cato.md` (inline `role`/`style` fallback). Opening releases pointer lock but swaps the canvas CSS cursor to the pixel triangle; `updateEdgeScroll`/camera keys early-return while `dialogOpen`. Pixel font `zpix.woff2` via `fonts.json`, 24px.
- **RPG typewriter + pagination (2026-07-20):** Cato's reply reveals **char-by-char** (`showDialogText`→`startTypingPage`, a `time.addEvent` per-char `TYPE_MS=50` — cozy pace), and text that overflows the box is **paginated** (`paginate` — a hidden design-sized measuring div, `measureEl`, binary-searches the largest prefix whose rendered height ≤ `DIALOG_FIT_H`; wrapping is scale-invariant so design-scale measuring is exact). **No scroll**: when a page is full and more remain, a **"more" arrow** shows bottom-right of the box (`cato-more-icon` HUD image, `all_icons` atlas frame `play-brown` — a TAN triangle, so it's **tinted dark** `#3f2c18` or it's invisible on the tan box; alpha-pulses). **Advance** = click anywhere (incl. ON the box, see click-through below) / Space (guarded so it doesn't fire while the chat input is focused) / tap → `advanceDialog()`: snap the typing page complete, else next page; returns false when all shown so the same gesture then **closes** the dialog. Greetings / "thinking…" / error lines use `setImmediateDialog` (instant, one page, resets pagination).
  - **Box is deliberately short** — `chat-message` + `cato-dialog-text` are **700×130** (~2 lines; small so normal replies paginate), `DIALOG_FIT_H=118` (box − margin for the arrow + font rounding). `cato-dialog-text` uses **`align:start`** (start-of-line per language — left for LTR, right for RTL — NOT centered). The box BOTTOM is anchored (`offsetY -60`, origin bottom), so it shrinks from the TOP: the more-arrow (anchored to the box bottom) needs no change on a resize, but the **portrait + name frame must move with the box TOP** (they sit just above it — `cato-portrait -191`, `cato-name-frame`/`-text -192` for the 130-tall box; retune both if you change the height).
  - **Click-through fix (`makeDialogTextClickThrough`, called on open):** the SDK renders `text-area` widgets as DOM `<div>` overlays with `pointer-events:auto` (z-index **99980**), which SWALLOW clicks landing ON the box — so advancing only worked clicking OUTSIDE (where the click reaches the canvas). These divs are display-only, so we set them `pointer-events:none`; clicks then fall to the canvas and `advanceDialog` fires. The chat-input-field (text-**input**, z-index **99990**) keeps its pointer events so the player can still click it to type.
  - Assets: `public/uploaded/all_icons.{png,json}` (hand-authored atlas-json, one region `play-brown` at 144,48 16×16) + a manifest `assets[]` entry. Dev key **M** shows a long multi-page reply to exercise it without the AI.
  - **First-render gotcha (`catoDialogText` pre-seed):** Phaser's DataManager emits `setdata` (not `changedata`) on a key's FIRST set, and the SDK text-area only listens for `changedata-<binding>`. So the very first `registry.set('catoDialogText', …)` (the open greeting) silently stayed on the "…" fallback. Fixed by pre-seeding `registry.set('catoDialogText','')` once at scene setup (in `buildFindCatButton`) so every real line is a `changedata`.
- **Game-state awareness (2026-07-18):** each turn `submitDialog` sends `buildObservation()` as the `observation` — the **backpack** (items aggregated by name + counts) + a **farm** summary (crops by type, ripe / growing / thirsty counts, empty tilled soil). So Cato can answer "what seeds do we have / anything ripe / room to plant" and act sensibly (don't offer a crop whose seeds aren't in the bag). This is the **cheap state-injection layer BEFORE a real tool-agent** — the SDK `Npc` already keeps + sends conversation history, and the game holds all state locally, so we just hand it over. **Roadmap** (see memory / the design discussion): recipes into the observation when a crafting system lands; a client-orchestrated query-tool **agent loop** when lookups get large; **persistent per-player NPC memory** (ADR-019, a `summary` + pinned `facts` store consolidated by a Haiku call) is a SEPARATE axis, deferred until the game systems are built out.

## Save data — auto-save + restore (2026-07-18)
Persists the whole game per (game, user) with the platform primitive **`umicat.saves`** (signed-in → backend via home-ui `useUmicatRpcHost` → game-manager `GameSaveService`; anonymous/standalone → localStorage `umicat:saves:standalone:state` — no auth branching in game code). Key `state`.
- **What:** `buildSave`/`applySave` (blob `v:1`) serialize the backpack (`{id,count}` → `itemFromId` rebuilds full stacks — the single factory, also used by `setupInventory`), hotbar selection, `tilled` cells, per-cell `soilWet` (remaining ms), crops (`{key,name,stage,timer}`), and Cato's position. `restoreCrop` rebuilds crop sprites at their stage; soil is re-autotiled after all tilled cells load. **v1 does NOT simulate offline growth** — timers restore as-saved.
- **Auto-save:** `scheduleSave()` debounces **700ms** after any mutation — hooked into `publishInventory` (covers inventory + selection) + till / plant / water / Cato-till / crop stage-advance. Plus a 15s periodic backstop + a save on tab hide / `pagehide`. Short debounce is deliberate: the backend write is async and a save-on-**close** can't flush as the page tears down, so the state must reach the backend **while the tab is open**.
- **Never wipe the save — two guards (both bugs were hit):** (1) **`saveArmed`** — saving is armed ONLY after `loadGame` has actually READ the store (found or empty); a slow load or read error leaves it disarmed, so the default state can never overwrite the real save before it's restored. (2) The world + hotbar are **hidden behind a "Loading…" cover** (`showLoadingCover`/`markReady`, `gameReady` flag) until the save is applied — no flash of the empty farm; an 8s fallback + the init-failure path always reveal. (Also: do NOT bind destructive dev keys like a bare `saves.delete` — a stray K press wiped saves.)

## World / camera plumbing (stable)
- Scene-as-data: `water` + `grass-island` tilemap layers; world 1280×720; camera bounds = the **water** tilemap extent (`camera.bounds: { fitTo }` in `main.json`) so you can't pan past the ocean. **RESIZE mode + adaptive integer zoom** (`computeZoom`, `referenceZoom: DESIGN_ZOOM=3`); pin origin via `originTopLeftScroll` — never `setOrigin(0,0)` (breaks tilemap culling).
- **Resolve tilemaps by NAME** (`'island'`/`'water'`), not hardcoded id — re-dragging changes the id and silently breaks colliders / camera `fitTo` (bit us twice). Collision via `addTilemapCollider` + `applyAssetHitbox`.
- **Pointer lock + custom cursor**: click captures the mouse, Esc releases; a VIRTUAL cursor (`vcursor`) driven by relative deltas, clamped to canvas; `handleLockedClick` routes clicks (hotbar → backpack → farming → portrait → cat → camera-release). Cursor rendered in `CursorScene` (top overlay). Editor iframe needs `allow="pointer-lock"` + `sandbox="allow-pointer-lock"` (home-ui `GameDetail.tsx`).

## Assets (real-user workflow)
Sprout Lands premium pack sheets are imported via the **Asset Manager** (region-tagged where needed) and synced into `public/uploaded/` — see memory `asset-manager-to-local-repo-sync` (pw-prod token → `GET /projects/{id}/assets` + `/regions` → download from `cdn.umicat.ai/uploads/{gameId}/`; author the atlas-json locally, `load.atlas`). Region-tagged: `inventory_spritesheet` (frame/slot), `tools_and_meterials` (hoe/axe/watering-can), `farming_plants_items` (seed bags + crops). Grid-sliced (no regions): `farming_plants` (growth), `watering_splash` (48×48!), `tools` (16×16 tool-use). The **premium character** sheet's last 4 rows were re-tagged in the Asset Manager `die-*` → **`water-*`** (frames 160-191); mirrored in `manifest.json`.

## Key files
- `GameScene.ts` — everything (world load, wander/leash, camera keys, pointer lock, farming, inventory model, Cato tasks, dialog).
- `HotbarScene.ts` / `InventoryScene.ts` / `CursorScene.ts` — overlay scenes (native px), registered in `main.ts`, launched by GameScene after the HUD exists.
- `BootScene.ts` — loads manifest + all uploaded atlases/sheets; registers the `water-splash` + `water-pour` anims.
- `public/scenes/manifest.json` — asset + animation table; `public/scenes/world/main.json` — the scene; `public/playbooks/cato.md` — Cato's persona + actions; `docs/design.md` — design.
